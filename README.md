# Android Emulator

An iOS client and cloud backend foundation for running Android APKs remotely. The iPhone app uploads APK files to a backend; later phases attach those APKs to an isolated Android runtime and stream the Android display back to iOS.

## Phase 1 status

Implemented in Phase 1:

- SwiftUI iOS application for selecting and uploading `.apk` files;
- editable backend URL in the iOS app;
- APK library fetched from the backend;
- FastAPI health endpoint;
- safe APK upload validation and storage;
- SHA-256 metadata and SQLite index;
- automated backend tests;
- automated iOS tests and device build;
- downloadable unsigned/re-signable `.ipa` generated by GitHub Actions;
- Docker image definition for the backend.

Not implemented yet:

- Android/ReDroid runtime;
- ADB install/launch session lifecycle;
- Android display streaming;
- WebRTC signaling/player;
- touch-to-Android input mapping;
- audio/gamepad support.

Those features are Phase 2 and Phase 3 of the approved design.

## Backend API

Current endpoints:

```text
GET  /health
GET  /v1/apks
POST /v1/apks
```

`POST /v1/apks` accepts multipart form-data with a field named `file`. Only filenames ending in `.apk` are accepted. The configured maximum upload size defaults to 512 MiB.

Uploaded files are stored with generated UUID filenames rather than user-supplied paths. Metadata is stored in SQLite.

### Environment variables

Copy `.env.example` values into the server environment:

```dotenv
ANDROID_EMULATOR_DATA_DIR=./data
ANDROID_EMULATOR_MAX_APK_BYTES=536870912
```

## Run backend with Python

Requires Python 3.12+.

```bash
cd backend
python -m pip install -e '.[test]'
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Tests:

```bash
cd backend
python -m pytest -v
```

## Run backend with Docker

```bash
docker build -t android-emulator-backend ./backend
docker run --rm \
  -p 8000:8000 \
  -v android-emulator-data:/data \
  android-emulator-backend
```

Then `GET /health` should return:

```json
{"status":"ok"}
```

## iOS app

The iOS project is defined in `ios/project.yml` and generated with XcodeGen. The app currently provides:

- **Add APK** file picker;
- uploaded APK library;
- upload/loading/error states;
- pull-to-refresh;
- **Settings** screen for the backend URL.

The development default backend URL is `http://127.0.0.1:8000`. On a physical iPhone this must be changed in Settings to a backend address that the iPhone can actually reach.

## Get the IPA without a PC

Open the repository's **Actions** tab and run/open **Build iOS IPA**. A successful run uploads an artifact named:

```text
AndroidEmulator-unsigned-ipa
```

Inside it is:

```text
AndroidEmulator-unsigned.ipa
```

This IPA contains an unsigned iPhone device build. It is intentionally prepared for later re-signing. It will not install on a normal iPhone until it is signed with a valid iOS certificate/provisioning profile or another compatible signing method.

No signing certificate, provisioning profile, Apple account credential, or private key is committed to this repository.

## Security notes

APK files are treated as untrusted input. The backend never uses the uploaded filename as the storage path. In later phases, ADB and the Android runtime must remain on a private network and must not be exposed directly to the internet.

The current iOS `Info.plist` permits arbitrary HTTP loads to make early development against a non-TLS backend possible. Production deployment should use HTTPS and tighten App Transport Security before distribution.

## Roadmap

### Phase 2 — Android runtime

- deploy ReDroid on Linux;
- introduce the `AndroidRuntime` backend interface;
- create/start/stop Android sessions;
- connect ADB privately;
- install APKs and launch packages.

### Phase 3 — interactive streaming

- capture Android display;
- WebRTC signaling and media transport;
- iOS video player;
- touch coordinate mapping and input injection;
- audio.

### Phase 4 — hardening

- authentication;
- multi-user isolation;
- persistence controls;
- recovery/reconnect behavior;
- gamepad mapping;
- production database/object storage when needed.
